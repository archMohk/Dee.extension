DeeW.Clean

Batch-cleans local and cloud Revit models: purges unused elements, deletes zero-area rooms and unused groups, flags in-place families for review — then saves or Synchronizes With Central so the cleanup reaches the real shared model, not a disconnected copy.

Risk level: High Unlike DeeW.Sharing/Batch Save to Cloud (which always detach and only ever create a NEW, separate Cloud Model), DeeW.Clean deliberately opens the REAL central or cloud model without detaching, deletes elements in it, and pushes those changes back via Synchronize With Central — including on live ACC Cloud Models other people may have open. Test on a backup/non-production project first.

What it does

For every selected local file or cloud model, runs whichever checks you enabled and then saves the result back:

  • Purge Unused Elements — uses Revit's own Document.GetUnusedElements API (the same set the "Purge Unused" dialog shows), run iteratively until nothing more can be purged. Needs Revit 2024 or later; on older Revit this step is skipped with a clear note rather than failing the file.
  • Delete Zero-Area Rooms — rooms with Area ≤ 0 (Unplaced or Not Enclosed), same detection rule as DeeCleaner's interactive scan.
  • Delete Unused Groups — Model/Detail Group types with zero placed instances anywhere in the project, same rule as DeeCleaner.
  • Flag In-Place Families — counted and reported, never deleted automatically. An in-place family is real modeled geometry, not an "unused" element by any Revit definition — this is intentionally the one check that stays report-only, matching DeeCleaner's own restraint.

Local Standalone files are simply saved in place. Local workshared files and ACC Cloud Models are opened without detaching and pushed back to their real central via Document.SynchronizeWithCentral — the whole point is cleaning the actual shared model, not a disconnected copy.

How to use it

  1. Under Local Files: browse to a folder and click Scan Folder, or Add Files... for specific files.
  2. Under Cloud Models: click Add Cloud Models... to browse ACC by Hub/Project and pick which cloud models to include.
  3. Tick the files/models you want to process.
  4. Switch to Options: choose which checks to run, set a Synchronize Comment, and review the other settings.
  5. Click Run — the Log & Report tab shows live progress (current file, elapsed/ETA).
  6. Use Export Report for a full Excel/CSV/TXT record of what was purged/deleted per file.

Options

Purge Unused ElementsRequires Revit 2024+; older Revit sessions skip this step per file with a clear warning rather than failing.
Delete Zero-Area Rooms / Delete Unused GroupsSame detection rules as DeeCleaner's interactive scans.
Flag In-Place FamiliesReport-only — counts them in the report so you can review and remove manually if wanted; never auto-deleted.
Synchronize CommentThe comment written to the model's Synchronize With Central history, so teammates can see what a run changed.
Compact Central File on SynchronizeOff by default — reduces central file size but increases sync time.
Audit on OpenRuns Revit's file audit when opening local files.
Automatically Resolve DialogsAuto-dismisses Revit's native dialogs so a batch never blocks on a modal prompt.

Before you run it

  • This is a brand-new button in the existing DeeW.Cloud dropdown, so a plain pyRevit Reload is enough — no restart or cache-clear needed.
  • Runs on pyRevit's default IronPython 2 engine from the start, same as every other tool in Dee.extension.
  • Document.GetUnusedElements needs live verification on a real Revit 2024+ session — check the report's Warnings column after your first run for a "needs Revit 2024+" note if it was skipped unexpectedly.
  • Opening a file the scanner classifies as "Central" (vs. "Local Copy of Central") directly and Synchronizing from it is unusual — a closed file's header can't always reliably tell the two apart, so both are treated the same way here. Best practice is always working from a local copy.
  • Cloud models are opened via OpenAndActivateDocument, which switches Revit's visible active tab to each file in turn while the batch runs — expected behavior (same as DeeOpener/DeeNWCs), not a bug.
  • Make sure Revit itself is signed in to your Autodesk account for cloud models, separately from the ACC browsing sign-in.
  • Test on a backup/non-production copy of a project first — this tool deletes elements and synchronizes automatically, with no per-file confirmation.

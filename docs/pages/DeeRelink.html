LazyPack

DeeRelink

Scans every Revit Link in each currently-open document and lets you batch-update their file paths - one tab per open document, since more than one project can be open in the same Revit session.

Risk level: Medium Clicking Apply actually reloads/relinks the checked links from their new paths right away - there's no separate preview/confirm step per row, only the New Path text itself. Double-check paths before clicking Apply, especially if you typed them by hand.

What it does

For every open, non-linked document, one tab (named after that document) lists every Revit Link (RevitLinkType) found in it: File Name, Current Path, and an editable New Path column. Local/server-hosted links read their path via the link's own external file reference; ACC/BIM 360 Cloud Model links use a different, cloud-specific API (Revit deliberately doesn't expose cloud links the same way as local ones) and show as [ACC Cloud Model] Project ... / Model ....

Set a New Path two ways: type a local path directly, or highlight one or more rows and click Browse for New Folder (Highlighted)... to pick one folder and apply it to all of them at once (matching each link's own file name inside that folder). To relink to a different ACC cloud model, highlight rows and click Pick from ACC Cloud (Highlighted)... and applies your pick to every highlighted row. Either kind of target works for either kind of currently-hosted link - relinking a cloud link to a local file, or a local link to a cloud model, are both supported. Click Apply to actually relink every row with a target set - this is the same operation as Revit's own "Manage Links > Reload From..." command, run via the API.

The ACC Hub/Project you pick is remembered (shown at the top of the window) so you're only asked once, not on every use - click Change ACC Project... to switch it deliberately. Once inside that project, Pick from ACC Cloud lets you navigate the folder tree one level at a time and only scans a folder's Revit files when you explicitly choose "Scan This Folder for Revit Files" at whatever level you've navigated to - it never scans the whole project. Each folder's scan result is cached, so returning to the same folder later offers "Use Cached" instead of hitting the ACC API again.

How to use it

  1. Open DeeRelink - it scans every currently-open document automatically and gives each one its own tab.
  2. Switch to the tab for the project you want to fix.
  3. Type a New Path for a broken/moved link, or highlight several rows and use Browse for New Folder (Highlighted)... if they all moved to the same new local folder.
  4. For a cloud target: click Pick from ACC Cloud (Highlighted)... - the first time ever, it asks you to pick a Hub and Project (remembered afterward); then navigate into subfolders one at a time, and pick "Scan This Folder for Revit Files" once you've reached the folder you want (with an option to include subfolders), then select the model.
  5. Click Apply - the tab rescans itself afterward so the grid always reflects Revit's actual current state, and a report window shows exactly what succeeded or failed per link.
  6. Use Rescan any time to refresh the list without applying anything (e.g. after fixing something outside DeeRelink).

Options

New PathFree-text, editable per row. Empty means "no change" for that row - Apply only acts on rows with something set here (typed, Browsed, or picked from ACC).
Browse for New Folder (Highlighted)...Picks one local folder and sets New Path for every highlighted row to "that folder + the link's own file name" - useful when a whole batch of links moved together.
Pick from ACC Cloud (Highlighted)...Uses the remembered Hub/Project (see Change ACC Project below), then navigates the folder tree one level at a time - nothing is scanned until you explicitly choose "Scan This Folder for Revit Files" at whatever folder you've reached, with a This-Folder-Only vs Include-Subfolders choice. Only signs in to Autodesk when you click this button, never automatically.
Change ACC Project...Re-prompts the Hub/Project pickers and remembers your new choice for next time - use this to switch which ACC project "Pick from ACC Cloud" browses into.
ApplyRelinks every row with a New Path/cloud target set, via Revit's own link-reload API. Rows are unaffected if nothing is set.
RescanRe-reads the document's links from scratch, discarding any unapplied New Path text you've typed.

Before you run it

  • This is a brand-new button in a panel that also got its icon size changed (see below), so it needs a full Revit restart + pyrevit caches clear --all to appear the first time.
  • Relinking uses RevitLinkType.LoadFrom, the same API behind Revit's "Reload From..." command - it needs no Transaction (deliberately not wrapped in one here, unlike everything else in this extension), but it still really changes the document the moment you click Apply.
  • Whether a relinked link keeps the same internal element id afterward isn't fully documented - DeeRelink rescans the whole tab after every Apply rather than assuming, so the grid always reflects Revit's real current state either way.
  • Cloud link path reading uses Revit's GetExternalResourceReferences API and tries several plausible key names for the ACC project/model GUIDs (the exact key names aren't fully documented) - if a cloud link's Current Path can't be resolved this way, it shows a generic "(Cloud Model)" label instead of guessing wrong.
  • Try it on a backup/non-production project first, especially for links you're not sure about the exact intended new path.

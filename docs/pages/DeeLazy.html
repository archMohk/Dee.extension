LazyPack

DeeLazy

A growing collection of bulk productivity tools, opened from one card-based launcher window. Each tool is its own self-contained module - adding a future one never touches the existing ones. Tools so far: View Cropping, Fill Pattern Conversion.

Risk level: Medium Every Crop Action inside View Cropping applies immediately once you click it - after a confirmation dialog showing how many views will be affected, but with no separate staged preview/Apply step. Double-check your checked rows and offset values before clicking an action button. Fill Pattern Conversion is lower-risk by comparison - it only ever creates new elements, never edits or deletes an existing pattern.

What it does

Opening DeeLazy shows a launcher window with one card per available tool. Clicking Open on a card opens that tool's own window - the launcher itself does nothing else.

View Cropping

Batch-edits Crop Region settings across many views at once: Crop Region Active, Crop Region Visibility (Show/Hide/Toggle), Annotation Crop (Yes/No), Crop Offset (Top/Bottom/Left/Right or a single Uniform value, in your project's display units), and Scope Box assignment/removal. Supports Floor Plans, Ceiling Plans, Sections, Elevations, Detail Views, Drafting Views, and 3D Views (Schedules, Legends, Renderings, and Sheets themselves are not views with a crop region and are excluded).

Load views via Current Sheet, Selected Sheets..., Entire Project, or Current Selection (Project Browser or a viewport on a sheet - Revit's Selection API doesn't distinguish the two, so there is only one button for both). Narrow the list with Filters (View Type, Discipline, View Template, Name/Sheet text search, Dependent/Primary, current Crop Active/Annotation Crop state), then check the rows you want and click a Crop Action on the right. Each action shows a Yes/No confirmation naming how many views are affected, then runs immediately inside one Transaction with a progress bar, and lists every view's result in the Report grid at the bottom right - export it to Excel any time with Export Report....

Fill Pattern Conversion

Converts Fill Patterns between the two Revit pattern Targets: a Model pattern's line spacing is a real-world size that scales with the view (denser at a coarser scale, sparser at a finer one); a Drafting pattern's spacing is a fixed paper size, the same at any view scale. For each checked pattern, this creates a brand-new pattern with the opposite Target and its grid geometry (line spacing, dash/gap lengths) scaled by a Reference Scale you set per row - e.g. converting a Model pattern at Reference Scale 100 "locks in" what it would look like on paper at 1:100. The original pattern is never edited or deleted, so anything already using it (a Material's surface pattern, a Filled Region Type, ...) is completely unaffected.

How to use it

View Cropping:

  1. Open DeeLazy from the LazyPack panel, then click Open on the View Cropping card.
  2. Load views with one of the four buttons on the left (Current Sheet / Selected Sheets / Entire Project / Current Selection).
  3. Optionally set Filters and click Apply Filters to narrow the list, and/or type in the Search box above the grid.
  4. Check the views you want in the middle grid - use Select All, Select None, or Invert Selection to speed this up. Checked rows stay checked even if a later filter/search hides them.
  5. Click a Crop Action on the right (Enable/Disable Crop Region, Show/Hide/Toggle Visibility, Enable/Disable Annotation Crop, Apply Crop Offset, Assign/Remove Scope Box) - confirm the view count in the dialog that appears.
  6. Check the Report grid (or the printed HTML report) for what succeeded and what was skipped/failed and why, and use Export Report... to save an Excel copy if needed.

Fill Pattern Conversion:

  1. Open DeeLazy, then click Open on the Fill Pattern Conversion card - it scans every fill pattern in the project automatically.
  2. Check the pattern(s) you want to convert (Select All / Select None / Invert Selection help with a long list). Solid Fill patterns can't be converted (no grid geometry to scale) and are always skipped even if checked.
  3. Set each checked row's Reference Scale (default 100, meaning 1:100) - edit it directly in the grid, per pattern, since different patterns may need different reference scales.
  4. Optionally change the Model/Drafting Suffix fields - the New Name column updates live as you type.
  5. Click Convert Selected and confirm the count. Check the pyRevit output window for what was created and what was skipped (and why - usually a duplicate name).

Options

Crop Offset - UniformWhen checked, one value is applied to all four sides instead of separate Top/Bottom/Left/Right values.
Crop Offset signPositive values expand the existing crop box outward on that side; negative values shrink it inward. This is a relative nudge to whatever crop each view already has, not an absolute size.
Assign Scope Box...Lists every Scope Box in the project by name and assigns the one you pick to every checked view.
Remove Scope BoxClears the Scope Box assignment (sets it to none) on every checked view.
Filters (View Cropping)Narrow the loaded list before selecting - View Type, Discipline, View Template, Name/Sheet text, Dependent-only/Primary-only, and current Crop Active/Annotation Crop state. Filters only hide rows; they don't change what's checked.
Reference Scale (Fill Pattern Conversion)Per-row, e.g. 100 for 1:100. Model→Drafting divides the pattern's line spacing by this number; Drafting→Model multiplies by it.
Model / Drafting SuffixAppended to the original pattern's name to build the new pattern's name (default " (Model)" / " (Drafting)"). If a pattern with that exact name already exists, the row is skipped rather than overwritten.

Before you run it

  • This is a brand-new button in an existing panel, so it needs a full Revit restart + pyrevit caches clear --all to appear the first time.
  • Crop Region Shape (non-rectangular shapes, matching/duplicating a shape between views), split-crop regions, Far Clip Offset, and View Depth are intentionally not included in View Cropping's first release - only the core crop properties above are.
  • "Annotation Crop" is read/written by parameter NAME ("Annotation Crop"), not a fixed internal enum - if a view doesn't expose a parameter by that exact name, its row shows "(n/a)" and any action on it reports "not found" rather than guessing.
  • Each View Cropping action runs inside one Transaction across all checked views - if you Undo in Revit afterward, it undoes the whole batch at once, not one view at a time. Same for a Fill Pattern Conversion run - Undo removes every newly-created pattern from that run in one step.
  • Try View Cropping on a handful of views first, especially for Crop Offset, to confirm the direction/units match what you expect before running it across an entire project.
  • Fill Pattern Conversion is brand-new and unverified against a live project - in particular, whether a converted pattern's line ORIGIN (not just spacing) needs adjusting hasn't been confirmed. If a converted pattern's lines look offset/misaligned compared to the original, that's the first thing to check.

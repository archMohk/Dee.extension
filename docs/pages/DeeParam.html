HealthPack

DeeParam

Audit every shared and project parameter in the model, find orphans, compare against the shared parameter file, remove or extend bindings, bind from the file, and export to Excel.

Risk level: Medium Removing a binding discards every value stored in that parameter, and deleting an orphan removes the shared parameter element from the model. Every change shows a preview and asks before it runs, and Revit's Undo reverts it.

What it does

  • Scan — lists every parameter bound in the model (Manage > Project Parameters) with Kind (Shared / Project), Scope (Instance / Type), Categories, Storage, Data Type, Group, GUID, and how many elements carry it, how many have a value, and how many distinct values there are. Usage is counted over at most the number of elements in the "Probe up to" box per parameter, so a large model stays scannable; the Used column says "x of y probed" when it hit the cap.
  • Orphans — shared parameters loaded into the model but bound to nothing (left behind by a removed binding or a purged family) are listed as "Shared (unbound)" in orange. No other DeePack tool could see these.
  • Shared parameter file — Load Shared Parameter File reads the file set under Manage > Shared Parameters and fills the File Status column: In file, Not in file (red), or Name differs (yellow).
  • Delete / Purge — Remove Binding (checked) and Delete Orphaned Shared (checked). Check Unused and Check Orphans pick the usual candidates in one click.
  • Rebind / Repair — Extend Checked adds the selected categories to an existing binding, keeping its Instance/Type kind. Bind Checked Orphans and Bind File-Only Parameters create a new binding from the file's definition, Instance or Type per the radio.
  • Export to Excel — writes the rows currently shown to a themed .xlsx.

Four tabs sit over the one scan:

  • Parameters — the audit grid above, with Delete / Purge and Rebind / Repair.
  • By Category — pick a category on the left to see every parameter bound to it, what else each one is bound to, and its usage. Unbind Checked takes this one category out of a binding (a parameter whose only category this was loses its whole binding). Add Parameters Checked on the Parameters Tab extends those parameters to this category.
  • Validation — a small dashboard: six tiles (parameters, filled values, empty values, overall filled %, fully filled and never filled parameters) and a grid with Carrying / Filled / Empty / % and a green-red bar per parameter. Filter to Below 100%, Below 50% or Never filled, or by category. Select Empty Elements in Revit hands the empty elements of the highlighted parameter to Revit's selection so they can be filled from the Properties palette. Export Validation writes the shown rows to Excel.
  • Add Parameter — name, data type, Properties-palette group, shared parameter file group, Instance or Type, vary-by-group, and the categories to bind to. Revit's API only creates shared-backed parameters, so the definition goes into the shared parameter file and is then bound to the model.

How to use it

  1. Click Scan Parameters. Use Filter, Kind and Group by to narrow the grid.
  2. Optionally click Load Shared Parameter File to see which shared parameters match the file.
  3. Tick the rows to act on (double-click a row toggles it), or use Check Unused / Check Orphans.
  4. For Extend or Bind, select one or more categories in the list first and pick Instance or Type.
  5. Click the action. Read the preview in the log, then confirm.
  6. Scan again to refresh the grid after a change.

Before you run it

  • "Unused" means no probed element carries a non-empty value. Raise the probe limit on a big model before trusting it for a delete.
  • A binding is removed by name and an orphan is deleted by GUID, each looked up fresh right before its own change, so a long list is safe to run in one go.
  • Binding from the file needs a shared parameter file set in Revit. The tool never creates or edits that file.
  • Each action is one transaction, so one Ctrl+Z reverts it.

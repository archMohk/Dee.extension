DeeW.Sharing

Converts Revit models into Autodesk Construction Cloud Cloud Models — detects each model's type, detaches from central and enables worksharing where needed, uploads to your chosen ACC Hub/Project/Folder, and reports the result.

Risk level: High This tool detaches models from central, enables worksharing, and uploads new Cloud Models to Autodesk Construction Cloud — none of these are easily reversible. Test on a backup/non-production copy of a project first, and confirm your ACC destination is correct before running on real files.

What it does

For every selected .rvt file: determines whether it's Standalone, Central, a Local Copy of Central, already a Cloud Model, Detached, Corrupted, or Read-Only; opens it with the right strategy (detaching and preserving worksets for Central/Local Copy models, opening normally for Standalone, skipping anything already in the cloud); enables worksharing if requested and not already enabled; then calls Revit's own Document.SaveAsCloudModel to upload it into the ACC Hub/Project/Folder you picked. Every step is logged and reported.

ACC Hub, Project, and Folder are all loaded by name via Autodesk's Data Management API — you never type or need to know a GUID. The folder step lets you drill down through nested subfolders (not only the project's top-level folders) — pick a folder to descend into it, or choose "Use This Folder" at any level to stop there, so the Cloud Model lands at the real path your project actually uses. Note that the actual upload uses Revit's own Autodesk sign-in (the account signed into Revit itself, top-right corner) separately from the sign-in used just to browse hub/project/folder names.

How to use it

  1. Browse to a source folder and click Scan Folder — every .rvt file is listed with its detected type, worksharing status, version, and size. Or click Add Files... to add specific .rvt files one at a time (multi-select supported) instead of scanning a whole folder — the two can be combined freely, and duplicates are skipped automatically.
  2. Tick the models you want to convert (Select All / Unselect All available). Check the Version Check column — it flags any file whose own saved Revit version differs from the Revit session you're running right now, since Revit silently upgrades a file to the current version the moment it's opened.
  3. Switch to ACC Destination & Options, click Pick ACC Destination..., and choose your Hub, Project, and Folder by name.
  4. Set your processing options (Enable Worksharing, Detach, Audit, Compact, etc.).
  5. Click Run — review the Log & Report tab as it processes.
  6. Use Export Report for an Excel/CSV/TXT record.

Options

Enable WorksharingRuns Document.EnableWorksharing with Revit's own default workset names ("Shared Levels and Grids" / "Workset1") if the model isn't already workshared.
Detach from Central AutomaticallyApplies to Central and Local Copy models only; Standalone models open normally, Cloud models are skipped.
Preserve / Discard Existing WorksetsWhich detach behavior to use when detaching is enabled.
Audit / Compact / Open All WorksetsStandard Revit open/save options, applied per file.
Automatically Resolve DialogsAuto-dismisses Revit's native dialogs (missing links/families, upgrade notices, etc.) so a batch never blocks on a modal prompt.
Overwrite / Rename Duplicate Cloud ModelIf a cloud model with the same name already exists: Rename appends "(2)", "(3)", etc.; Overwrite does not delete/replace the existing cloud item (that would need an unverified, destructive API call) — it skips the file instead and says so clearly in the report.
Generate Report / Close File After ProcessingSelf-explanatory; Close After Processing keeps memory use low across many files.

Before you run it

  • This is a brand-new dropdown (DeeW.Cloud) with brand-new buttons, so it needs a full Revit restart + pyrevit caches clear --all to appear the first time — a plain Reload isn't enough.
  • This package was originally built to run on pyRevit's CPython 3 engine, but live testing found that engine crashes at the .NET level before any script runs at all (confirmed in both Revit 2024 and Revit 2026, two different failures) — DeeW.Cloud now runs on pyRevit's default IronPython 2 engine instead, the same as every other tool in Dee.extension.
  • Make sure Revit itself is signed in to your Autodesk account (top-right corner) — the actual cloud upload uses that sign-in, separately from the ACC browsing step.
  • Several Revit API details used here (cloud-model detection, the cloud model's GUID after upload, "Open All Worksets") are flagged in the code as needing live-Revit verification — check the report's Warnings/Errors columns after your first real run.
  • Autodesk's ACC/Data Management API has no field for "this project's official Revit version" — a Cloud Model's version is simply whatever Revit session saves it. The Version Check column compares each file against the Revit you're currently running instead, which is the version any newly-uploaded Cloud Model will actually end up in.
  • Try it on a backup/non-production copy of a project first.

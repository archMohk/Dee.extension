HealthPack

DeeGetDWG

Finds every CAD Import/Link (DWG, DXF, etc.) in the document and shows how far its placement point is from the Internal Origin - the usual cause of Revit's "very far from the origin" warning and the view-navigation/performance problems that go with it. Check the far ones, click one button, and they're back at (0,0,0).

Risk level: Medium Moving a CAD file this far changes its position relative to everything else in the model - if other elements were placed relative to that CAD file's old location, they'll now look wrong relative to it and may need repositioning too. It also unpins the file automatically if it was pinned. There's no separate confirm step beyond checking the row and clicking Apply - review the list before moving anything.

What it does

Scans the active document for every ImportInstance - Revit's element type for both "Import CAD" and "Link CAD" - and reads each one's placement point (its Transform's Origin) in the model's internal coordinate system. The Internal Origin is always exactly (0,0,0) in that system, so the distance shown for each row is a direct, reliable measurement, not an estimate.

Checked rows get two things done, in one Transaction: if the file is Pinned, it's unpinned; then it's translated (moved, never rotated or rescaled) so its placement point lands exactly on (0,0,0). Everything else about the file - its rotation, its scale, its layers - is untouched.

How to use it

  1. Open DeeGetDWG - it scans automatically and lists every CAD Import/Link, farthest first.
  2. Rows farther than the threshold field (1000 by default, in your project's display units) are pre-checked for you. Adjust the number and click Apply Threshold to re-check based on a different distance, or use Select All / Select None to override manually - any row can be checked or unchecked by hand regardless of the threshold.
  3. Click Move Selected to Internal Origin. There's no confirmation dialog - review your checkboxes before clicking.
  4. Check the pyRevit output window for the result: how many moved, how many were skipped, and why (pinned-but-owned-by-another-user, group membership, etc.) - nothing ever stops the batch, a problem row is simply skipped and reported.

Options

Auto-check items farther thanA distance in your project's display units (feet, meters, etc. - whatever the project is set to). Rows beyond it are pre-checked whenever you scan or click Apply Threshold; this is just a starting point, not a filter - every row is always listed and can be checked by hand.
RescanRe-reads every CAD Import/Link from scratch - useful after moving something outside DeeGetDWG, or after Undo.

Before you run it

  • This is a brand-new button in an existing panel, so it needs a full Revit restart + pyrevit caches clear --all to appear the first time.
  • Only affects CAD Imports/Links that are direct children of the currently active document - a DWG linked into a separate linked Revit model isn't reached from here.
  • Skipped automatically, with a reason shown in the report: CAD instances that are members of a Group, and (in workshared models) ones currently owned by another user.
  • Everything runs in one Transaction - Undo (Ctrl+Z) reverts every unpin/move from one click at once.
  • If elements elsewhere in the model were positioned relative to the CAD file's old far-away location, moving the file will make that relationship look wrong until you also fix those elements.

LazyPack

DeeReLevel

Change one or more Level elevations while automatically preserving the real-world position of everything hosted or constrained to them — the goal is to move the Level, not the building.

Risk level: High This tool edits Level elevations and then rewrites offset-type parameters on every wall, floor, roof, ceiling, hosted family, and MEP run referencing those Levels, across the whole model, in one operation. Always run Scan Project and Preview Changes first, review the Preview tab, and try it on a non-production/backup copy of a project before trusting it on live work.

What it does

By default, moving a Revit Level moves the entire building with it, because every hosted element's "offset from level" parameter stays the same while the level itself shifts. DeeReLevel does the opposite: for every affected element it recalculates the matching offset parameter (Base Offset, Sill Height, Height Offset From Level, an MEP run's Offset, etc.) so that level elevation + offset — the element's actual real-world elevation — comes out exactly the same as before. Only the Level moves; nothing else does.

Coverage spans walls, floors, roofs, ceilings, doors, windows, railings, stairs, rooms/areas, generic models, casework, furniture, specialty equipment, architectural & structural columns, foundations, and the full MEP set (pipes, ducts, cable trays, conduits, flex pipes/ducts, fittings, accessories, mechanical/plumbing/electrical/lighting fixtures, sprinklers, fire protection equipment). Rebar, Rooms/Areas, and annotation categories (Spot Elevations, Dimensions, Detail Components, Reference Planes) are scanned and reported but never modified, since they follow their host or reference geometry automatically. Structural Framing has no reliable single offset parameter, so it's moved directly instead (see the warning badge it gets in Preview).

Hosting relationships are never touched — DeeReLevel only ever edits Level and offset-type instance parameters, so a wall-hosted door stays hosted exactly as it was. Group members are never moved individually (that would corrupt the group); if a fallback move is ever needed on a grouped element, the whole Group instance is moved once instead.

How to use it

  1. Click Scan Project — every Level is listed with its current elevation and hosted-element count.
  2. Type a new value into New Elevation for each Level you want to change, and tick its Select checkbox.
  3. Click Preview Changes — review the Preview / Affected Elements tab: which elements will be adjusted automatically ("ok"), which need manual verification after applying ("warning" — sloped MEP runs and Structural Framing), and which are report-only.
  4. Check the Log & Errors tab for any warnings (e.g. two levels ending up at the same elevation).
  5. Click Apply Changes and confirm — each Level is applied in its own transaction, so one Level's failure doesn't roll back a different Level's already-applied changes.
  6. Use Export Report to save an Excel (3-sheet: Levels, Affected Elements, Errors/Warnings) or JSON record of what happened.

Before you run it

  • This is a brand-new button, so it needs a full Revit restart + pyrevit caches clear --all to appear the first time — a plain Reload isn't enough.
  • Every BuiltInParameter this tool relies on has a defensive fallback and is designed to degrade gracefully if wrong for your Revit version, but the parameter-to-category mapping has not been confirmed against a live project yet — check the Preview tab's Parameter/Old Value/New Value columns look sensible before applying.
  • Sloped MEP runs (pipes/ducts under slope) are adjusted by shifting their whole run's Offset parameter by the same amount the Level moved — mathematically this preserves both endpoint elevations and the slope, but it depends on how Revit internally drives a sloped run's geometry from that parameter. Preview flags every sloped MEP element for manual verification after applying.
  • Structural Framing (beams) always uses a direct geometric move rather than a parameter edit, since no single reliable offset parameter was assumed for it — verify analytical model alignment afterward.
  • Try it on a backup/non-production copy of a project first, especially for MEP-heavy or structurally complex models.
